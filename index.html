AI

My perspective

I treat AI as an engineering tool, not a shortcut around thinking. It speeds up the parts of a problem I already understand, but it doesn't replace understanding them. The engineer is still on the hook for the result, so I lean on my own judgment, verify what the tools give me, and keep a solid grasp of the fundamentals underneath.

Tools I use

I'm comfortable working with ChatGPT and Claude, GitHub Copilot for inline suggestions, and AI-assisted IDEs like Cursor. Each one fits a slightly different moment in my workflow, and I switch between them depending on what I'm trying to get done.

How I use it

Mostly for debugging, learning new concepts, generating boilerplate, and rubber-ducking my way through a problem. Talking through my reasoning with a model often surfaces the assumption I got wrong faster than staring at the code alone.

My workflow

The loop usually goes: scaffold and generate boilerplate first, get unfamiliar errors explained, explore a few different approaches, then verify and test the results independently before I trust any of it. I'm especially cautious with embedded and low-level work, where AI output is more likely to be subtly wrong and correctness matters most, so I lean harder on my own testing and hardware-level reasoning there.
